# Task-based usability review

Status: prepared; no participants have completed this protocol. No success rate or outside endorsement is claimed.

Recruit 3–5 people, preferably including a procurement analyst and someone unfamiliar with the project. Do not coach them during tasks. Obtain consent before recording. Store contact details privately, outside this public repository.

| Task | Observable completion | Target |
|---|---|---|
| Find Home Office in Buyer exposure | Correct identity and eligible/attributable coverage located | Within 90 seconds |
| Explain what recorded award value means | Does not call it payments or realized revenue | Without prompting |
| Challenge the concentration conclusion | Finds process interval and largest-award sensitivity | Within 2 minutes |
| Inspect validation evidence | Separates original audit from automated name screening | Correct denominator |
| Download follow-up cases | Opens the review queue and identifies an evidence URL | Within 90 seconds |
| Repeat on a phone or narrow screen | Can navigate, read tables, and reach evidence links | No blocked task |
| Navigate with keyboard only | Can reach tour, section controls, search, download and original links; focus visible | No keyboard trap |

Record task completion, time, errors, confidence (1–5), observed confusion, device/viewport and accessibility tools used. These targets are usability goals, not measured results. Ask “What does this number mean?” before offering an explanation.

Triage: blocked task or misleading financial interpretation is high priority; a recoverable navigation issue is medium; cosmetic preference is low. After changes, repeat only affected tasks and report participant count and remaining failures. Do not infer population usability from a small convenience sample.

Use `data/review/usability_feedback.csv` for anonymized findings. It is intentionally empty until actual observations exist.
