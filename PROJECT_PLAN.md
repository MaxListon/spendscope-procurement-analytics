# Twelve-to-sixteen-week development plan

This is a proposed part-time development and validation schedule, not a claim of elapsed work. The initial implementation is a working foundation; completing the validation below provides the depth expected of a multi-month portfolio project.

| Weeks | Work | Evidence of completion |
|---|---|---|
| 1–2 | Audit source partitions, schema changes, licensing and selected-universe coverage | Source audit with reconciled process/award counts and explicit exclusions |
| 3–4 | Refine SQL warehouse, revision handling and accounting grains | Known-answer tests; documented contract and reconciliation results |
| 5–6 | Manually validate registered-ID conflicts and name-only matches | Labeled sample, false-merge/false-split review and correction policy |
| 7–8 | Extend R sensitivity work to process-clustered resampling and buyer threshold comparisons | Executed report comparing assumptions and identifying unstable conclusions |
| 9–10 | Conduct focused category and buyer case studies | Three short evidence-linked business memos, with defensible recommendations |
| 11–12 | Dashboard accessibility, performance and usability review | Recorded task walkthroughs and fixes from actual feedback |
| 13–14 | Clean-environment reproduction, source-update rehearsal and CI deployment | Successful remote real-data build and release notes |
| 15–16 | Independent review, documentation and interview rehearsal | Reviewer issues resolved; ability to explain every metric without a script |

Prioritize validated business findings over adding languages or infrastructure. Do not claim realized organizational impact without an actual stakeholder deployment and measurement.
